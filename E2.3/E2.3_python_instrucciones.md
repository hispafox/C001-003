# E2.3 — Alucinaciones: Cuando la IA se Equivoca

## Contexto

Curso "IA Generativa para el Desarrollo: Herramientas". Agentes de IA generan el código completo.
**Principio**: La IA es la HERRAMIENTA, las apps son el PRODUCTO. Cero API keys en el código.

## Objetivo Didáctico

Entrenar el **pensamiento crítico** del desarrollador: demostrar empíricamente que los agentes de IA generan código con APIs, métodos y librerías **inexistentes** si no se verifica. Construir una herramienta que automatice la detección de estas alucinaciones.

**Mensaje clave**: "La IA genera código que PARECE correcto pero puede contener referencias a cosas que NO EXISTEN. SIEMPRE verificar."

---

## Prompt para el Agente de IA

```
Crea una herramienta Python que detecte alucinaciones en código generado
por IA. La herramienta analiza snippets de código Python y verifica si
las librerías, clases y métodos referenciados existen realmente.

CLASE HallucinationDetector:
- __init__(self): inicializa conjuntos de módulos estándar conocidos
- check_imports(self, code: str) -> list[dict]: analiza los imports
  del código con ast.parse y verifica:
  - ¿El módulo existe? (importlib.util.find_spec)
  - ¿El atributo importado existe en el módulo?
  Devuelve lista de {module, attribute, exists, hallucination, detail}
- check_methods(self, code: str, known_fakes: list[str]) -> list[dict]:
  busca llamadas a métodos conocidos como falsos (lista proporcionada)
  Devuelve lista de {method, line, hallucination, detail}
- analyze(self, code: str, label: str = "") -> dict: análisis completo
  Devuelve {label, imports, methods, total_issues, verdict}
  verdict: "LIMPIO" si 0 issues, "SOSPECHOSO" si 1-2, "PELIGROSO" si 3+

SNIPPETS DE PRUEBA (10 snippets embebidos):
5 con alucinaciones (código que parece correcto pero usa cosas falsas):
1. "import pandasql" — librería real PERO "pandasql.execute_query()" no existe
2. "from sklearn.neural import DeepClassifier" — módulo inventado
3. "import fastutils" — librería completamente inventada
4. "df.auto_optimize()" — método inventado de pandas DataFrame
5. "from collections import TreeDict" — clase inventada en módulo real

5 sin alucinaciones (código correcto):
6. "import json" + "json.dumps()" — correcto
7. "from pathlib import Path" + "Path.exists()" — correcto
8. "from collections import Counter" + "Counter.most_common()" — correcto
9. "import csv" + "csv.reader()" — correcto
10. "from datetime import datetime" + "datetime.now()" — correcto

DEMO:
- Analizar los 10 snippets y mostrar resultado por cada uno
- Tabla resumen: snippet, veredicto, issues encontradas
- Estadísticas: aciertos del detector

10 TESTS:
1. Detecta "import fastutils" como alucinación (módulo no existe)
2. Detecta "from sklearn.neural import X" como alucinación
3. Detecta "from collections import TreeDict" como alucinación
4. NO marca "import json" como alucinación
5. NO marca "from pathlib import Path" como alucinación
6. NO marca "from collections import Counter" como alucinación
7. Detecta método falso "auto_optimize" cuando está en known_fakes
8. analyze() devuelve verdict "LIMPIO" para código correcto
9. analyze() devuelve verdict distinto de "LIMPIO" para código con alucinaciones
10. Código vacío no lanza error

CLI modo dual: sin args → demo + tests.
Docstrings Google Style, type hints. Solo librería estándar.
```

| Snippets | ¿Los 10 snippets son realistas y educativos? |
