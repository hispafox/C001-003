## Objetivo Didáctico

Demostrar que un agente de IA puede generar una **API REST completa y funcional** a partir de una especificación en lenguaje natural. El alumno comprueba que la IA genera endpoints, validación, respuestas JSON y códigos HTTP correctos al primer intento.

## Prompt para el Agente de IA

```
Crea una API REST con Flask para gestionar tareas. Requisitos:

MODELO DE DATOS (diccionario en memoria):
- id: int (autoincremental)
- title: str (obligatorio, 1-100 caracteres)
- description: str (opcional, max 500 caracteres)
- status: str (pending, in_progress, completed) — default: pending
- created_at: str (ISO 8601, automático)
- updated_at: str (ISO 8601, automático al modificar)

ENDPOINTS:
- GET /api/tasks — listar todas (con filtro opcional ?status=pending)
- GET /api/tasks/<id> — obtener una tarea
- POST /api/tasks — crear tarea (JSON body: title, description, status)
- PUT /api/tasks/<id> — actualizar tarea (campos parciales permitidos)
- DELETE /api/tasks/<id> — eliminar tarea
- GET /api/tasks/stats — estadísticas (total, por estado, última creada)

VALIDACIÓN:
- title obligatorio y 1-100 chars en POST
- status debe ser uno de los 3 valores permitidos
- id inexistente devuelve 404 con mensaje JSON
- body inválido devuelve 400 con mensaje JSON descriptivo

RESPUESTAS:
- Siempre JSON con estructura consistente
- 200 para GET/PUT exitosos
- 201 para POST exitoso
- 204 para DELETE exitoso
- 400 para validación fallida
- 404 para recurso no encontrado

EXTRAS:
- Datos iniciales: 3 tareas de ejemplo (sobre desarrollo de software)
- Logging de cada request
- CORS headers básicos (Access-Control-Allow-Origin: *)
- Docstrings Google Style y type hints

MODO DUAL:
- Si se ejecuta directamente: arranca el servidor Flask en puerto 5000
- Si se importa: expone la app para testing
- Incluir función run_tests() que pruebe TODOS los endpoints
  con el test client de Flask (app.test_client())
- 12 tests: GET all, GET one, GET not found, POST valid, POST invalid
  (sin title, title vacío, status inválido), PUT valid, PUT not found,
  DELETE valid, DELETE not found, GET stats, filtro por status
```

---

## Especificación Técnica

### Archivo: `e2_1_task_api.py`

### Estructura:
1. Diccionario global `tasks = {}` + contador `next_id`
2. Función `init_sample_data()` que crea 3 tareas de ejemplo
3. Función `validate_task(data, required=True)` para validación
4. Decorador/función para CORS headers
5. 6 endpoints (ver arriba)
6. `run_tests()` con app.test_client() y 12 asserts
7. `if __name__`: si args `--test` → run_tests(), sino → app.run()

### Tests (12):
1. GET /api/tasks → 200, lista con 3 tareas iniciales
2. GET /api/tasks/1 → 200, tarea con id=1
3. GET /api/tasks/999 → 404
4. POST con title válido → 201
5. POST sin title → 400
6. POST con title vacío ("") → 400
7. POST con status inválido → 400
8. PUT /api/tasks/1 con nuevo title → 200
9. PUT /api/tasks/999 → 404
10. DELETE /api/tasks/1 → 204
11. DELETE /api/tasks/999 → 404
12. GET /api/tasks/stats → 200 con total y conteos por estado
