## Objetivo Didáctico

Demostrar que **cada elemento del prompt mejora el resultado**. Se pide la misma tarea 8 veces, añadiendo un elemento cada vez: contexto, rol, público, acción, restricciones, ejemplos, tono y longitud. El alumno ve cómo la calidad del código mejora progresivamente.

---

## Prompt para el Agente de IA

```
Crea un script Python educativo que demuestre los 8 elementos de un
buen prompt. El script contiene 8 funciones de validación de email,
cada una generada con un prompt progresivamente mejor:

FUNCIÓN 1 — Solo acción (prompt vago):
  "Valida un email"
  → validate_v1(email) — implementación mínima, solo @

FUNCIÓN 2 — + Contexto:
  "En un sistema de registro de usuarios, valida un email"
  → validate_v2(email) — añade verificación de dominio

FUNCIÓN 3 — + Rol:
  "Eres un desarrollador senior backend. En un sistema de registro..."
  → validate_v3(email) — añade regex más completa

FUNCIÓN 4 — + Público objetivo:
  "...para un equipo de juniors que mantendrá el código..."
  → validate_v4(email) — añade comentarios explicativos

FUNCIÓN 5 — + Restricciones:
  "...sin dependencias externas, solo re. Máximo 30 líneas..."
  → validate_v5(email) — código conciso y sin imports extra

FUNCIÓN 6 — + Ejemplos:
  "...estos emails son válidos: user@domain.com, name+tag@sub.domain.org.
  Estos son inválidos: @domain.com, user@, user@.com, user@domain..com"
  → validate_v6(email) — maneja todos los edge cases de los ejemplos

FUNCIÓN 7 — + Tono:
  "...documenta con docstrings Google Style, nombres descriptivos..."
  → validate_v7(email) — documentación profesional

FUNCIÓN 8 — Prompt completo (los 8 elementos):
  Combina todo en un prompt perfecto
  → validate_v8(email) — versión final production-ready
  Devuelve dict: {valid, email, errors[], checks_passed[]}

DEMO: probar las 8 funciones con 10 emails de test (5 válidos +
5 inválidos) y mostrar tabla comparativa de aciertos.

CLASE PromptAnalyzer:
- analyze_progression() -> dict: muestra qué mejora cada versión
- compare_all(test_emails) -> tabla con resultados por versión
- get_prompt_for_version(version) -> str: devuelve el prompt usado

10 TESTS:
1. v1 acepta "user@domain.com" (básico)
2. v1 falla con "user@.com" (demasiado simple)
3. v6 rechaza "user@.com" (los ejemplos lo cubren)
4. v6 rechaza "user@domain..com" (edge case)
5. v8 acepta "user+tag@sub.domain.org" (complejo válido)
6. v8 rechaza "@domain.com" (sin local part)
7. v8 devuelve dict con claves correctas
8. v8 errors es lista vacía para email válido
9. v8 errors contiene mensaje para email inválido
10. compare_all devuelve resultados para las 8 versiones

Docstrings Google Style, type hints. Solo librería estándar.
```
